## 2. 通知トリガー変更の案内は撤回しました

**前版の「項目が作成または変更されたとき」へ変更する案内は誤りでした。実施しないでください。** 通知は新しい案件IDの行を作成したときだけです。既存の「項目が作成されたとき」を維持します。

現在の問題は、Teamsで新規案件を開始してもListsに新しい行が作成されないことです。更新時通知を追加して代用しません。

既存PAは入力textをConversationIdとして既存行を検索し、見つかった場合は既存行を更新します。以前ユーザーから提供されたTeams実行結果では、項目の作成がスキップされ、既存項目の更新が成功していました。Teams側の実際のConversationIdと取得済みCaseIdを確認し、新規案件の判定・ID発行に進まない理由を調べる必要があります。Teamsの「新しい会話」で実際のIDが変わるかはまだ未確認です。

## 3. 同じTeams投稿で、3つを一緒に確認する

動作確認用の会話で、前置きなしの **「台所でガス臭い」** を送ります。

1. Teamsに②③④の読みやすい回答が出る。会話内の続報では①も出る。
2. 新規案件では新しい案件IDを発行し、それと一致するLists行が新規作成される。既存案件の追加報告は同じ行を更新する。この2つを別々に確認する。
3. 新規IDの行が作成されたときだけ、既存の通知フローからTeamsへカード／AppsのURLが届く。

続けてテスト報告を追加し、同じ案件のLatestStatusが更新され、追加の新規案件通知が出ないことを確認します。別案件を開始した場合は、新ID・新行・新規通知が必要です。

確認票は `validation/通し確認.csv` にあります。変更後の実機試験は全件NOT_RUNです。
