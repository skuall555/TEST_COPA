## 2. Listsの「更新」でも通知フローを起動する

**これはPA側で1か所の設定変更が必要です。コードの貼り替えだけでは通知条件は変わりません。** 変更するのは既存の通知フローです。「AI_案件保存更新」ではありません。Listsの列追加やAppsの作り直しは行いません。

以前の画面で確認した通知フローは、上から次の3段でした。

```text
項目が作成されたとき
  ↓
作成（Compose）
  ↓
アダプティブカードを投稿して応答を待機する
```

この最初のトリガーを、SharePointの **「項目が作成または変更されたとき」** へ変更します。「項目の作成」アクションを追加する操作ではありません。

### 操作

1. [以前の通知フローが見えていた環境のフロー一覧](https://make.powerautomate.com/environments/Default-45efe66a-3822-4ba9-b35b-216704c8976a/flows)を開き、**「項目が作成されたとき → チャットまたはチャネルでメッセージを投稿する」** を開きます。
2. 「名前を付けて保存」でバックアップ用コピーを作成し、コピーはオフのままにします。以後は**元のフロー**を編集します。
3. **編集**を押し、最上段「項目が作成されたとき」の「…」から削除します。下のCompose・Teamsカードは削除しません。
4. 最上段で「トリガーを追加する」→SharePoint→ **「項目が作成または変更されたとき」** を選びます。
5. 元と同じサイト・リストを設定します。

| 項目 | 実際に確認できた保存先 |
|---|---|
| サイトのアドレス | `https://tokyogasgroup.sharepoint.com/sites/NW_tool_library` |
| リスト名 | `AI_エージェント可視化` |
| リストGUID（一覧に出ずカスタム値が必要な場合） | `6905d4ae-958e-4e9c-97c7-5170c9c2dfa8` |

6. Compose・カードの既存の入力が有効か確認し、**保存**します。削除したトリガーの動的項目にエラーが付いた場合は、元と同じ名前の列を新トリガーの動的コンテンツから選び直します。赤いエラーがある状態では運用を再開せず、その項目を確認します。
7. 元の通知フローがオンであることを確認します。バックアップの方はオンにしません。

トリガーはポーリング等の検知待ちがあるため、Lists保存と通知の開始時刻は一致しない場合があります。待ち時間の実測は未取得です。カードが応答待ちの場合、通知が届いていても実行履歴全体は実行中のままになることがあります。

以前の3段以外にListsへ書き戻す処理が追加されている場合は、変更で通知が連鎖しないよう適用前に確認します。今回のフロー全体のエクスポートは未取得なので、この手順だけで保存・接続・受信成功が検証済みとはしません。

## 3. 同じTeams投稿で、3つを一緒に確認する

動作確認用の会話で、前置きなしの **「台所でガス臭い」** を送ります。

1. Teamsに②③④の読みやすい回答が出る。会話内の続報では①も出る。
2. 回答の「案件ID」と一致するLists行が作成または更新される。**新しい行がないだけで未保存とはしません。** 現行PAはConversationIdで既存行を探す方式です。
3. 通知用フローの新しい実行ができ、Teamsへ既存カード／AppsのURLが届く。

続けてテスト報告を追加し、同じ案件の**LatestStatusの更新でも通知が届く**ことを確認します。単に新規作成時の通知が届くだけでは2点目の解消確認にしません。

確認票は `validation/通し確認.csv` にあります。変更後の実機試験は全件NOT_RUNです。
