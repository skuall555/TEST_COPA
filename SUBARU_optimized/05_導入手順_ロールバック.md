# 試験導入手順とロールバック

## 事前保全

1. 本番のソリューション／エージェントをエクスポートし、現行3トピック・全体指示・フロー接続参照・ナレッジ設定・公開バージョン・日時を保存する。添付ファイルと実際の現行版が一致するか確認し、異なる場合は差分を確認してから試験する。
2. **本番を上書きせず**、同一ソリューションから検証用エージェント／環境を複製する。検証用コピーには既存フロー・原本Word・SharePoint・Index38文書・AI Builderを接続する。新規外部APIや追加フローは不要。
3. コピー先の論理スキーマ名、dialog、knowledgeSources、flowId、画像aIModelIdが添付と一致するか確認する。異なる場合はIDを推測で置換しない。コピー先の正規エクスポートと対応表を作り、対象を特定して別途レビューする。接続先が存在しない場合はそこで導入を止める。
4. 複製トピックを同じエージェント内で追加するだけではトリガー競合を起こす。検証用エージェント内の対応する3トピックを更新し、重複した入口・画像トピックを有効にしない。停止済み2-巡回は有効化しない。

## 検証用への適用

1. `1-マニュアル関連入口_optimized.yaml`の**全文**を、検証用の対応トピックのコードエディターへ貼り付けて保存する。
2. 同様に`3-9-緊急保安業務エージェント_optimized.yaml`、`4-9-画像分析エージェント_緊急保安_optimized.yaml`を全文適用する。部分抜粋ではない。
3. 全体指示を`SUBARU_エージェント指示_optimized.txt`で更新する。既存のチャネル設定・生成設定・ナレッジ接続は勝手に変えない。
4. コードエディターの構文／ノードエラー、トピックチェッカー、Power Fxの型・プロパティ参照エラーを全て確認する。特に入れ子へのGoto、Filter/Split内のValue、CreateSearchQueryのSearchQuery型、新規Topic文字列変数、条件付き結合、OnActivity割り込みを確認する。YAMLパーサーの成功だけで次へ進めない。
5. 各フローが有効で、検証者の接続参照・実行権限があること、Wordナレッジが同期済みであること、画像AI Builder入力ContextText／ImageInputと出力predictionOutput.textが接続済みであることを確認する。認証値をYAMLへ貼らない。
6. 最初は公開せずテストペインで実行する。ES/R2確認、条件探索、改訂選択・継続・終了、現場優先度・修理番号、写真1〜3枚と復帰、明示計測をスモーク検証する。
7. 04の35ケースを新旧同条件で実行し、トレースを比較する。原本Wordを開き、変更前・変更後の全文・変更対象外の一致・列挙／表／注記の完全性を照合する。
8. 要領取得失敗・原文0件・途中切れ・不合格・複数ROWの一部不備をテストし、虚偽の成功が出ないことを確認する。画像の事実とユーザー申告を区別できるか確認する。
9. 安全系、重複回答、番号横取り、画像履歴、原文真正性を含む必須ケースを承認できた後、組織の承認手順で本番への適用・公開を実施する。このパックの作成時点では、Copilot Studioへの変更・公開は行っていない。

## 導入判断

必要なIDや接続が欠ける、読込／型検査エラーが残る、原文・安全性の試験が失敗する場合は本番へ進めない。応答時間だけ改善していても必須機能が失われた場合は不採用とする。50%短縮は実測するまで承認根拠にしない。

## ロールバック

1. 検証用の新トピック／エージェントを無効化し、旧エクスポートの3トピックと全体指示を戻す。本番へ未適用なら本番の変更は不要。
2. 本番へ適用済みの場合は事前保存した公開バージョン／ソリューションへ戻し、接続参照とナレッジIDを確認して再公開する。コードだけ戻して全体指示を残さない。
3. 古い会話スタックと新しい会話を混在させず、新規セッションで3分岐、番号入力、画像1・2枚目と復帰を確認する。
4. 案件保存フローが書き込んだ記録はYAMLのロールバックでは戻らない。検証データを識別して管理する。原本Wordは今回もロールバック時も更新しない。
