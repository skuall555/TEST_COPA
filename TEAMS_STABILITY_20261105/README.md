## 何を変更したか

- 入口の目的分類が「現場対応アドバイス」、かつガス臭・漏えい・検知・警報等の明示情報がある場合、既存の09緊急保安トピックへ直接渡します。「ガス」という単語だけでは近道へ入りません。この条件を満たす報告では、フォルダ選択のためのAI検索ガイド取得・再検索・フォルダ再分類を通りません。
- 確認・改訂は目的分類が異なるため、この近道へ入りません。不明な目的・明示情報のない入力は元の経路を使います。優先度を単語だけで決める処理は追加していません。
- 3-9の優先度生成が空または形式不合格なら、同じ現場入力・同じ固定ガイドを使って**最大1回だけ再生成**します。合格した初回に追加のモデル呼出しはしません。
- 再生成後も不合格なら、従来と同じく業務回答の送信・保存を止めます。検証を緩めたり、判定不能を安全扱いしたりしません。
- 失敗文に診断コードを付けます。今後は失敗画面の文章だけで、出力文字数・検証エラー・再試行回数を確認できます。診断の版は `subaru-runtime-20261105-v1` です。

前回のTeams用表示・会話内比較、既存Apps用7見出しの保存文章、PA入力・出力、判定ルール、修理／画像経路は維持しています。

## 実機での確認

エラー0件の確認後に公開し、コパスタで**新しいテストセッション**を始めて「台所でガス臭い」と送ります。前の会話の変数と混同しないよう、診断版も確認します。

- コパスタのテスト画面では、チャネル値により従来の7見出し表示になります。Teams公開版の `msteams` チャネルでは②③④、同じ会話の続報では①も表示します。
- 成功時の診断は `stage=wait|validation=合格`。`retry=0` は初回で合格、`retry=1` は自動再試行後の合格です。「優先度追加回答」が空なのは追加報告を待っている状態です。
- 不成立時は `stage=failed|...|retry=1` のコードが停止文に付きます。その文章を保存して、次の試行の変数で上書きしないようにします。
- 保存フローの実行履歴と、返された案件IDのLists行を照合します。Teamsの「新しい会話」操作でConversationIdが必ず変わるかは未確認です。現行PAはConversationId検索なので、既存行の更新と新規作成を区別します。
- 初回・追加報告・写真・確認・改訂・修理を回帰確認します。上位AIの自由回答や、古い公開セッションが使われる問題を、このYAMLだけで解決したとは扱いません。
