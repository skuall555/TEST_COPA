# Copilot Studio導入

変更するのは `4-9-画像分析エージェント_緊急保安` だけです。3-9、入口トピック、エージェント全体指示は変更しません。

> **2026-11-19訂正**
>
> `AI_画像一時保存_v3` をCopilot Studioから呼び出しません。画像保存は既存のPower Apps→Copilot Studio画像転送PAに統合します。
> 詳細は [00_Base64なし_既存画像転送PAへ統合.md](../power-automate/00_Base64なし_既存画像転送PAへ統合.md) を使ってください。

## 1. 先に確認すること

- `AI_画像座標更新` が保存済みでオン
- 既存のPower Apps→Copilot Studio画像転送PAでSharePoint一時保存が完了している
- SharePoint接続が正常
- PA単体テストで応答が返る

## 2. 座標更新PAだけをツールとして使う

1. Copilot Studioで対象エージェントを開きます。
2. 「ツール」を開きます。
3. 「ツールの追加」→「フロー」を選びます。
4. `AI_画像座標更新` だけを使用します。
5. 入力名と順番は変えません。`record_id` 欄にはConversationIdを渡します。

`AI_画像一時保存_v3` はツールから外しますが、ロールバックのためテスト完了までPA自体は削除しません。

### AI_画像座標更新

入力：

- `text`：ConversationId（ツール画面の表示名は `record_id` のまま）
- `text_1`：image_token
- `text_2`：overlay_json
- `text_3`：analysis_note
- `text_4`：analysis_status

出力：

- `success`
- `error_code`

入力名・種類・順番は変更しません。変更するとCopilot Studio側の既存バインドが削除されるためです。

## 3. 使用するYAML

[4-9_画像座標対応_ツールdialog設定済み.yaml](4-9_画像座標対応_ツールdialog設定済み.yaml) を使います。

- 一時保存ツール呼び出しは削除済み
- `contentBytes`、`base64`、ファイル入力は無し
- 座標更新ツール `cr88f_SUBARU_search.action.AI__v3` だけを呼び出す
- Power Automate URLのフローID置換は不要

## 4. 現在の4-9をバックアップ

1. 「トピック」→ `4-9-画像分析エージェント_緊急保安` を開きます。
2. コードビューを開きます。
3. 全文を別ファイルへ保存します。
4. ファイル名に日付と「導入前」を付けます。

このバックアップがロールバック用です。

## 5. YAMLを貼り替える

1. `4-9_画像座標対応_ツールdialog設定済み.yaml` の全文をコピーします。
2. 4-9のコードビューを全選択して置き換えます。
3. 保存します。
4. トピックチェッカーを開きます。

次が0件であることを確認します。

- PowerFxError
- MissingRequiredProperty
- 未解決の変数
- 重複したアクションID

## 6. 今回追加した安全策

- 既存画像転送PAがAI分析呼び出し前にSharePoint保存を完了する
- 保存失敗でも画像分析は継続
- 座標は0〜1000の整数
- 1枚で最大8個の措置を別々にマーキング
- 関係ない画像・不鮮明画像には無理に座標を作らない
- 目印JSONが壊れていても従来の5見出しを破棄しない
- 座標は優先度・対応済み判定を変更しない
- 画像トークン一致時だけListsを更新
- 既存案件行のImage列だけを更新し、案件行がなければ新規作成しない
- 各マーカーにタップ時メッセージを持たせる

## 7. 公開前テスト

Copilot Studioのテスト画面で[テスト手順](../テスト手順.md)をすべて実施します。合格するまで公開しません。

## 8. ロールバック

保存エラーや既存画像分析の回帰が出た場合：

1. 4-9を導入前バックアップへ戻す
2. 保存
3. 座標更新PAをオフにし、既存画像転送PAを変更前コピーへ戻す
4. 既存案件のテキスト・画像分析を再テスト

3-9と既存案件保存PAを変更していないため、ロールバック範囲を限定できます。
