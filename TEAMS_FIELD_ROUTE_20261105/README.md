# Teamsの現場報告が「マニュアル確認」へ進む誤経路の修正

**今回貼り替えるのは「1-マニュアル関連入口」だけです。保存PA・通知PA・Lists列・Appsは変更しません。**

## 操作

1. [1_貼り替え用.txt](1_貼り替え用.txt) を開いて、コードの全文をコピーします。GitHubの表示なら「Raw」を押してから `Ctrl+A` → `Ctrl+C`。
2. コパスタの **「1-マニュアル関連入口」→コードエディター**へ全文を貼り替えて保存。エラー0件を確認して **公開**します。
3. **Teamsの同じエージェント**へ、前置きなしで「台所でガス臭い」と送ります。確認する最初のメッセージは次の文章です。

```text
現場報告を受け付けました。初動措置を判定します。
```

これは受付だけの表示です。保存完了を意味しません。その後、3-9の判定結果と、保存PAの新しい実行を確認します。今回の入口版は `Topic.実行バージョン = entry-field-first-20261105-v1`。

## 今回の証拠と、前回の誤り

ユーザー提供のTeamsの回答には、以下がありました。

- 入力は「台所でガス臭い」なのに「確認モード：文書内容確認」。
- Word原本取得失敗の文章と、A〜Eの検索枠だけの76文字。
- 保存PAの直近履歴は17:28のままで、今回のTeams試行時刻の実行がないとの報告。
- 取得失敗後に「マニュアル準拠」とする別の回答が続いている。

したがって今回の調査対象は、**現場報告が確認ルートに入り、現場保存まで到達していないこと**です。以前の別の実行で既存行更新が成功したことを、この試行にも当てはめません。取得失敗後の別回答を、今回の原本検索に基づく回答とは確認できません。

前回の近道は `answer_inferPurposeFromText` の後に置き、「目的分野＝現場対応アドバイス」が条件でした。AIが「マニュアル確認」と分類すると近道を使えませんでした。

今回、**明確な現場報告を、目的分類AIより前に既存3-9へ渡す**分岐を追加します。よって今回の入力では、目的分類AI・確認用Word検索・検索ガイド取得・フォルダ再分類を通しません。初動措置の優先度自体は、元の3-9のガイドと判定処理で決めます。単語だけで優先度を割り当てません。

## 保持する処理

- 元の入力文は変えません。小文字化は判別専用の別String変数だけです。
- 規定・基準・マニュアル・手順等が明示された依頼、用語の意味や条件付きの一般質問は、この近道へ強制せず元の意味分類を使います。
- 目的選択への番号回答は、元の質問と番号処理を維持します。
- 既存の確認・改訂の全アクション、原本検索・索引・保存フローの契約、3-9への論理名と引数を維持します。
- 3-9と画像トピックは今回貼り替えません。既に適用した判定・表示・再試行処理を使います。
- **通知は新IDのLists行が作成されたときだけです。作成・変更時の通知へ変える案内は撤回済みです。**

## 解消の確認条件

1. Teamsで「台所でガス臭い」が確認モード／Word原本取得失敗へ進まず、受付→現場判定へ進む。
2. 現場判定が合格し、**AI_案件保存更新**の実行履歴がその投稿時刻に増える。
3. **新規案件は新ID・新しいLists行が作られ、その作成に対して既存通知が届く。** PAが起動しただけでは完了にしません。
4. 追加報告は同じ案件の行を更新し、新規案件通知を増やさない。
5. Teamsの最終回答が、既に適用した読みやすい表示になり、無関係な一般回答・重複回答が続かない。

3の段階で既存行更新になった場合は、Teamsでの新規案件のキーとConversationId検索を確認します。今回の新データで確認できた「PA未起動」と、その後の「新規／既存の判定」を区別します。

**テナントでの上記試験は未実施。実機の解消・速度改善はまだ確認していません。** このYAMLだけで親エージェントの全ての自由回答を禁止できるとは扱いません。入口が起動しない・別回答が続く場合は、公開版とエージェントの実行経路・生成設定の確認が残ります。
