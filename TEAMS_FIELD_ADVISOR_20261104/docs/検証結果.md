# 検証結果・受入の扱い

**コード修正完了／本番動作未検証。** ローカルの式・YAML・模擬フローの検証と、Teams実機の受入試験を分けています。実行日時と件数は `validation/local_summary.json` を参照してください。

## 実行できたこと

- Python unittestで生成した実際のworkflow定義をテスト用WDL評価器へ読み込み、重複、案件／所有者の分離、前回比較、修理の同文保存、SharePoint障害を検証しました。SharePoint標準コネクターは模擬です。Microsoftの公式フロー実行エンジンではありません。
- Microsoft.PowerFx.Interpreter **1.8.1**、.NET SDK **8.0.426**で追加・変更式の構文と型、表示・比較9ケース、添付選択4ケースを実際に評価しました。通常版と接続版の両方を検証しました。Copilot Studio固有ホストの型推論・インポートの代替ではありません。
- 3トピックをYAMLとして読み込み、ID重複・Goto先の欠落がないことを確認。既存の全アクションIDを維持しました。
- 既存Apps用レンダラー `setVariable_itemRender` と、互換版の既存現場保存契約は変更前と一致。既存マニュアル確認／改訂の保存・遷移、ナレッジ検索、画像モデル・項目別特徴を保持していることを確認しました。目的分類への修理ルートの追記は意図した変更です。
- 実エクスポートへ定義を適用するツールが、元のID・表示名・メタデータと入力ディレクトリを保持することを模擬エクスポートで確認しました。

詳細は `validation/unittest.log`、`native_results.json`、`native_bound_results.json`。ネイティブの添付テストは仮文字列でImageInputの選択を確認したもので、**実写真の認識精度を検証したものではありません**。テスト用接続値は実接続版として配布していません。

## 後方互換の証拠と限界

`validation/legacy_renderer_before.txt` と `legacy_renderer_after.txt` は同じ式です。同じ判定行に対する従来形式の組立てを維持し、Teams表示のために保存用文章を再生成していません。`validation/*.diff` で変更範囲をレビューできます。

実際のPower Apps式・.msapp・本番保存サンプルは未取得です。そのため**実Appsの文字列パーサー回帰合格、画面表示合格は未確認**です。模擬テストの7見出しサンプルは本番ゴールデンデータではありません。導入時に本番サンプルと既存パーサーで必ず確認します。

## テストの再実行

パックのルートでREADMEのコマンドを実行します。Power Fxランナーは固定バージョンのNuGet依存を `/tmp/teams-native` へ取得します。個人情報は送信しません。接続版の式は、実値設定後に生成したディレクトリを `--topic-dir` へ指定できます。

```bash
python tools/native/run.py --dotnet /absolute/path/to/dotnet --topic-dir deployment-output/topics --result validation/native_deployment_results.json
```

実機の合格ログはCSVのstatusとevidenceへ追記します。模擬試験の成功をT01〜T19の合格へ転記しません。
