# Teamsだけ保存されない問題の調査票

**現時点の結論：真の書込み実行元・Teamsとの差は未確定。** リポジトリでは保存フロー呼出しを確認できましたが、実行履歴・接続・フロー本体はありません。設定変更済み、原因解消済みとは扱いません。

## 同じ条件で比較する

機密性のないテスト案件を使い、M365 Copilot正常回とスマホTeams失敗回で、入力文、エージェントID、環境、公開版、ユーザーを揃えます。以下の比較票はテナント管理者が埋めます。

| 確認項目 | M365正常回 | Teams回 |
|---|---|---|
| UTC投稿時刻・活動ID・会話ID | 未取得 | 未取得 |
| 実際の入口／現場／画像トピック実行 | 未取得 | 未取得 |
| 保存フローID・実行ID・開始終了時刻 | 未取得 | 未取得 |
| フロー実行者・接続所有者・接続参照 | 未取得 | 未取得 |
| text/text_1/text_2/text_3 または実入力 | 未取得 | 未取得 |
| 実際の作成／更新アクションのサイト・リスト・ID | 未取得 | 未取得 |
| SharePoint保存行ID・CaseId・種別・Created/Modified | 未取得 | 未取得 |
| Apps側Items条件・Refresh／タイマー | 未取得 | 未取得 |

## 履歴から次の確認を選ぶ

| 症状 | 操作・確認 | 対策の方向 |
|---|---|---|
| Teamsでトピック実行がない | Copilot Studioテストのアクティビティ追跡、分析／会話履歴で入口と3-9を確認 | 旧公開版・別環境・トピック無効・生成オーケストレーションの自由回答を修正。指示文の説明だけで「呼んだ」と判定しない |
| トピック実行あり、保存フロー履歴なし | 保存ノードへ到達したか、書式検証失敗分岐、画像単発経路、呼出し先IDの解決を確認 | 保存前停止の具体的エラーを修正。入口から必須保存ノードを明示的に通す |
| フロー実行あり、失敗 | Power Automate「実行履歴」の失敗アクションを開き入力・エラー・接続参照を比較 | 401/403なら認証と実行権限、400なら入力／列型、接続欠落なら接続参照を修正。ID・入力契約を想像で変更しない |
| フロー成功、保存行なし | SharePoint「項目の作成／更新」アクションがSucceededか、スキップされていないか。返却IDを実リストで開く | 別サイト／リスト、誤った更新ID、成功応答だけの分岐、後続削除や既存重複判定を確認 |
| 保存行あり、Appsに出ない | Appsの実データソース・フィルター、データ更新、種別／CaseId条件を確認 | 元の表示条件と新行の値を揃える。現場にAppsを開かせて代用しない |
| 保存直後の通知だけ遅い | 作成／更新時刻と下流フロー開始を比較 | 「項目が作成されたとき」の検知遅延を応答時間から分ける。これを最初の書込み元と誤認しない |

「ツール」一覧が空でも、YAMLからの `InvokeFlowAction` がある場合があります。一覧表示だけで保存処理なしと断定しません。フローIDを環境のソリューション／クラウドフローから照合してください。

## 修正を確定させる証拠

T01とT02について、投稿時刻、実行トピック、保存フロー実行ID、成功したSharePointアクション、実際の保存行ID、Apps表示を一組で残します。T09は修理回答のTeams文と保存列の文字列を改行・記号を含めて比較します。T15は同一活動IDの再試行と新しい投稿としての再送を区別します。

保存アダプターの模擬テスト合格だけでは、この調査票を「解決」にできません。実環境で特定できた原因、変更した設定、再検証の証拠を追記してください。
